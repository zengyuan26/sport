# 蓝脑星球培训讲师工作台：线上第一期设计

## 目标

把现有讲师 IP 工作台从本地原型变成一个只供内部使用、能长期保存资料的线上系统。第一期的重点是：打开即可进入、资料统一保存、后续更新功能时不覆盖老师资料。

## 使用边界

- 使用者是内部团队；讲师本人不注册、不登录。
- 第一期开一个共同入口密码。任何知道该密码的内部人员都可进入同一套团队资料。
- 系统沿用当前五张讲师卡和新增讲师入口；所有讲师共用一个团队资料库。
- 保留当前 IP 诊断、受众人群、内容创作和稿件诊断的互动流程，以及已设计好的示例数据与空白讲师引导。
- 第一阶段不做多人角色、操作记录、老师端、邀请码、文件上传、录音文件存储或复杂后台管理。
- 第一阶段不接入云端大模型或云端语音转写服务。现有的对话和诊断交互按原型的规则运行；浏览器语音能力可用时继续作为输入方式。真正的模型对话与语音转写单独作为第二期功能，避免在没有密钥、成本和提示词策略确认前假装它已具备真实判断能力。

## 访问与安全

### 选择

系统上线为非公开的内部网址。访问者先输入一个共同入口密码；密码通过部署环境的机密配置保存，页面与数据库里不保存明文密码。

### 会话

密码验证成功后，服务器创建一个 30 天有效的会话，并用仅服务器可读的安全 Cookie 保存会话凭据。退出或会话过期后需要重新输入入口密码。

### 明确取舍

共同密码不区分谁修改了什么，适合前期一两位内部人员快速共用；人员增加后，升级为个人账号、团队成员与操作记录，不改变讲师资料的数据结构。

## 数据与保存

### 团队工作空间

所有讲师数据存入一个共享的团队工作空间，而不是存入某个人的浏览器或个人账号。工作空间包含：

- 讲师卡、头像占位和当前选中的讲师；
- 新讲师的引导对话、对话摘要和重新诊断结果；
- IP 诊断中的身份信号、受众、产品/商业模式和叙事方向；
- 受众、压力、选题、情绪结构和粗稿；
- 已保存的参考风格卡及其样稿分析；
- 稿件诊断使用的草稿与当前界面选择。

### 数据库

使用托管 SQLite 数据库（D1）保存：

| 表 | 作用 |
| --- | --- |
| `team_workspace` | 唯一的一份共享工作空间 JSON、版本号和更新时间 |
| `access_sessions` | 已验证入口密码的会话摘要、过期时间 |

第一期将原型的完整工作状态保存在一条共享记录内，以低成本保持原有页面交互。每次保存都带版本号；如果另一位同事刚保存过，系统拒绝静默覆盖并提示刷新最新资料后再继续，避免“后保存的人覆盖前一个人”的数据丢失。

## 前端与服务端分工

- 静态页面继续承担 macOS 毛玻璃界面、讲师卡切换和内容创作的即时交互。
- 服务端只处理三个明确的责任：验证入口密码、维持会话、读取与保存共享工作空间。
- 浏览器本地存储只可用于临时界面状态，不能作为讲师资料的唯一来源。
- 网络异常时，页面保留当前输入并清晰提示“未同步”；恢复后允许用户再次保存。绝不把失败当成已保存。

## 发布与更新

- 网站代码和数据库分开发布。更新布局、页面或诊断规则只发布新代码，不清空数据库。
- 数据库结构变更使用追加式迁移；已发布的迁移不回写、不重置。
- 每次发布前进行脚本语法检查、接口行为检查、共享保存冲突检查和生产构建检查。
- 上线地址保持私有访问；部署完成后交付内部使用网址。GitHub 仓库继续只保存程序与数据库结构，不保存老师的真实资料、入口密码或会话信息。

## 第一期开箱流程

1. 内部人员打开工作台网址，输入共同入口密码。
2. 系统读取共享讲师卡；首次使用时显示空状态和“新增老师”。
3. 新老师从“让我们了解你”的引导对话开始，系统逐步形成 IP 诊断和受众/商业判断。
4. 内容创作按“目的 → 人群/压力/选题 → 情绪与十步结构 → 写作风格 → 粗稿”的既有流程完成。
5. 任意改变都会在短暂等待后同步到服务器；页面显示保存失败时，使用者可重试而不会丢失正在编辑的内容。

## 验收标准

- 非登录状态无法读取或保存讲师资料。
- 使用共同密码进入后，任意浏览器都能看到同一套已保存的讲师资料。
- 新增或修改讲师内容后刷新页面，数据仍存在。
- 发布页面更新后，数据库里已有的讲师资料仍存在。
- 两个浏览器同时编辑时，后保存的一方不会无提示地覆盖已更新的数据。
- 原型的四个主模块、讲师卡选择与新增讲师的空白引导仍可操作。
